\section{Introduction}
Reproducing experiments is important to advance science, but it's a time-consuming activity for scientists, without much reward.
LLMs are a promising tool for fully automating reproduction of experiments that only need computation.
This literature review examines work done in this area.

\section{Method}
The searh began with these papers [citation needed] from earlier work by Odd Erik Gundersen, Thijs Snelleman and Peter Lawrence. 
Almost all papers that cited (or were cited by) these papers, were classed as "not relevant", "relevant" or "very relevant".

These factors were used to assess papers:
\begin{itemize}
\item In which context was this paper cited? If the context is one of the later categories, then it is relevant.
\item If the context is not relevant, then the cited paper is also not relevant. (e.g. a list of papers that form a dataset for auto reproducibility)
\item Was this paper only cited in the bibliography, and not the main text? Then it is not relevant.
\item Does the paper's abstract relate to any of the categories. Then it's relevant. If not, then not relevant.
\item Some papers are borderline. They are listed here [TODO: compile list]
\end{itemize}

"Very relevant" papers were then used to expand the search, by assessing their citations and citers.

\subsection{Problem statement}
The field has not agreed on a common problem statement for automated reproducibility, 
and some authors who have contributed to the field had a slightly different problem in mind. 
This makes it difficult to compare performance across systems.
\begin{itemize}
    \item Artisan's \cite{artisan} problem statement is:
        \subitem "code generation task, where the agent generates a reproduction script that 
independently reproduces the paper’s reported results based on the code and data given in the artifact."
    \item Lin et. al. \cite{lin2025} do not define the problem explicitly, but rely on Paper2Code \cite{paper2code} for benchmarking.
    \item Paper2code \cite{paper2code}:
        \subitem Automatically produce a code repository that faithfully implements a methods and experiments in ML papers.
        \subitem The system is not given access to pre-existing artifacts
    \item Autoreproduce
        \subitem "..., given a paper P and instructions about experiment I, the agent A needs to reproduce the code 
        implementation of the method and experiment proposed in the paper Code = A(P, I), where Code is the output code."
\end{itemize}

\subsection{Validation}
Due to the differing problem statements, most papers primarily (sometimes exclusively) develop their own dataset of papers and scoring system.

Artisan-Bench \cite{artisan} consists of 23 curated software engineering papers papers with available and evaluated artifacts. 
The authors do not state why the benchmark has no negative examples. The benchmark has examples in python, java, rust, scala, ocaml and bash.

Paper2code \cite{paper2code} uses their own benchmark, Paper2CodeBench, to assess code generation. 
Reproducibility is not their main focus, but they run a small evaluation on 10 papers with human judges, and find that their system reproduces the papers 29.46\% of the time.

Lin et. al. \cite{lin2025} validate their solution by integrating with Paper2Code \cite{paper2code}, which enables easy testing against 
Paper2CodeBench \cite{paper2code} and PaperBench \cite{paperbench}.

\subsection{Agent Scaffolding}
The main difference between existing auto-reproducibility systems, is not the models they're using, but system prompts and scaffolding. 
Most use a multi-agent approach, where the task is decomposed sequentially, and specialized agents execute each task. 

Lin et. al. \cite{lin2025} aims to remove human-crafted system prompts and 
verification functions [TODO: find out what this is?] that are present in self-refine [citation needed].

Paper2code \cite{paper2code} draws inspiration from typical software development workflows, 
by decomposing the task into three coordinated stages: Planning, analysis and coding.

Autoreproduce \cite{autoreproduce} uses the paper lineage algorithm, developed by the authors, to examine citation relationships and associated code. 
This is done in order to uncover needed implicit domain knowlegde.
